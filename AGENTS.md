# QMvisualisation — инструкции для coding-агента

Проект: набор переиспользуемых Manim-инструментов для преподавания квантовой механики.

Перед работой:
1. Прочитай `AI/ARCHITECTURE.md`.
2. Прочитай `AI/CURRENT_TASK.md`.
3. Посмотри существующий код и переиспользуй рабочие решения.

Главные правила:
- Не переписывай рабочие сцены без необходимости.
- Не создавай абстракции «на будущее».
- Physics/core не должен импортировать Manim.
- `QuantumState` и `QuantumSystem` независимы и передаются в операции явно.
- В вычислениях используем натуральные единицы: `ħ = c = 1`.
- В показываемых студентам LaTeX-формулах фундаментальные константы пишем явно.
- Сцены остаются обычным Python/Manim-кодом, без YAML/JSON DSL.
- Сначала добейся работающего визуального результата, затем обобщай повторяющийся код.

Практические соглашения по репозиторию:
- Основная среда разработки — WSL-venv в `.venv` из корня проекта на диске D.
- Перед прямым запуском файлов из `example_scenes/` учитывай import path от корня проекта.
- Сгенерированные Manim-артефакты (`media/videos`, `media/generated_gifs`, `media/Tex`, `media/texts`) не коммитить без отдельной явной причины.
- Временные файлы для отладки, извлечённых кадров и разовых проверок хранить только в `media/tmp/`; не создавать временные каталоги в корне репозитория и удалять такие артефакты после использования.
- Если рендер требует системные зависимости (`latex`, `dvisvgm`, `ffmpeg`, `pkg-config`), фиксируй это явно в ответе.

## End-of-task handoff
После любой длинной многоступенчатой задачи закончи ответ блоком `HANDOFF`.
Максимум 10–15 строк.
Формат:

### HANDOFF
Status: done | partial | blocked

Done:
- 1–3 пункта
Changed:
- основные файлы/модули
Checks:
- какие тесты/рендеры запускались и результат
Issues:
- известные проблемы или `none`
Git:
- branch
- commit hash, если был создан
- working tree: clean/dirty
Next:
- один рекомендуемый следующий шаг
